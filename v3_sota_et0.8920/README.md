# SOTA 스냅샷 — Public 0.8812 (`submission.csv`)

배터리 열폭주 6단계 분류. 이 폴더는 Public 0.8812를 낸 제출 파일과, 그 파일을 그대로 재현하는 코드·가중치를 보존한 것입니다.

## 1. 실행
```bash
pip install -r requirements.txt
DATA=/path/to/battery_data_light          # train/ validation/ test/ sample_submission.csv

# (선택) 재학습: Train + Validation 전체 → weights/
python train.py --data_dir $DATA --vision_seeds 42,7 --alpha_trm1 0.06 --alpha_trm2 0.06

# 추론: weights/ 그대로 사용 (재학습 없이 submission.csv 재현)
python test.py --input $DATA/test/test.csv --image_root $DATA/test --output submission.csv
```
**재현성 확인 (2026-11-15):**
- `test.py`를 다시 실행하면 `submission.csv`와 완전히 같은 결과가 나옵니다 (다른 행 0개).
- Test를 실험 4개 / 7개로 나눠 따로 입력해도, 전체를 한 번에 넣었을 때와 같습니다 (다른 행 0개).
- 출력 행 순서는 입력 CSV 순서와 같습니다. `test.csv`의 순서는 `sample_submission.csv`와 같습니다.

## 2. 최종 구조
```
센서 CSV ─► 시계열 피처 166개 (features.py, mode='rich')
              ├─ 일반 실험 (tr_method 1) ──► LightGBM A (166개 피처)
              └─ 과충전 실험 (tr_method 2) ─► LightGBM C (153개: 압력 절대값·과충전 배율 제외)
                                                    │ P_시계열
열화상 ─► [현재−첫 프레임, 현재−15초 전, 현재−60초 전] ─► EfficientNet-B0 × seed 2개 평균 ─► P_이미지
                                                    │
            P = 0.94·P_시계열 + 0.06·P_이미지 ─► 인과적 단조 디코딩 (prefix Viterbi) ─► 라벨 1~6
```
- 모든 입력은 **같은 실험의 현재·과거 관측만** 씁니다. 시간 창은 행 수가 아니라 `relative_time_s`(초) 기준입니다.
- 학습 데이터는 Train(78개 실험) + Validation(19개 실험) 전체입니다. 클래스 가중치는 쓰지 않습니다.

## 3. 왜 이렇게 했는가

### 3-1. 처음부터 다시 만든 단순한 파이프라인
이전 파이프라인은 피처 735~822개에 클래스 균형 가중치를 썼습니다. 5-fold CV는 약 0.917까지 올랐지만 **Public은 0.857~0.866에서 멈췄고**, CV를 올린 변경들이 Public에서는 오히려 떨어졌습니다. 그래서 데이터 분석부터 다시 시작해, 근거가 확인된 피처만 남겼습니다.

| 결정 | 근거 |
|---|---|
| 가스 10종 제외 | 값의 15~50%가 0이고 몇 행마다 0과 양수를 오가는 노이즈. 넣으면 5-fold에서 손해 (−0.5점) |
| 주변 온도(`atmp_t`) 제외 | 단계와 무관 (단계별 중앙값 25.8~28.6°C). Test는 학습보다 낮아 범위를 벗어남 |
| `meas_a`, `meas_t1_plus_t2`, `indu_t.1` 제외 | 상수 / t1+t2와 동일 / Test에서 100% 결측 |
| `indu_t` 결측은 그대로 둠 | 실험 단위로 센서가 아예 없음. LightGBM이 NaN을 별도 분기로 처리 |
| 클래스 가중치 없음 | 5-fold에서 가중치 유무가 차이 없었고, 단순한 쪽을 택함 |
| 피처 세트 rich(166개) | 5-fold에서 compact(82개), 실험 기준 표현, z-score 추가, 압력 급등 피처 추가보다 모두 나음 |

결과: 새 파이프라인 첫 제출이 **Public 0.8716** (이전 최고 0.866 대비 +0.56점, 이전 모델과 86행 차이).

### 3-2. 라벨 구조에서 나온 피처
- **1→2:** t1 누적최대가 45.0~45.9°C일 때 전환 (97개 실험 전부) → "t1이 45/50/60/…°C를 처음 넘은 뒤 경과시간" 피처
- **3→4:** 전압이 실험 시작값의 약 80% 아래로 떨어질 때 (정확도 99%) → 전압비 누적최소, 하락 이후 경과시간
- **과충전 실험(tr_method 2):** 전압이 오르다 급락 → "전압이 최고점의 80% 아래로 떨어진 뒤 경과시간"
- 라벨은 실험 안에서 한 번도 내려가지 않음 → 인과적 단조 디코딩 (하이퍼파라미터 없음, 미래 행 미사용)

### 3-3. 과충전 실험 전용 모델 (C) — Test 분석에서 나온 결정
Test 실험 11개를 같은 그룹(배터리 종류 × tr_method)의 학습 실험과 입력 프로필로 비교했습니다. Test 라벨이나 점수는 쓰지 않았습니다.
- 학습 분포를 크게 벗어난 Test 실험은 **과충전 실험 3개뿐**이었고, 원인은 모두 **시작 압력**이었습니다. 각형 과충전 2개는 학습 범위의 4~9배였습니다.
- 그래서 과충전 실험은 압력의 **절대 수준** 대신 **상승분과 변화율**만 보는 모델로 예측합니다. 과충전 배율(`v_peak_ratio`)도 같은 이유로 뺐습니다(Test 각형 과충전 1개가 범위 이탈).

| 5-fold (Test 조건 평가) | 전체 | 과충전 | 각형 과충전 | Test 닮은 실험 |
|---|---|---|---|---|
| 모든 실험에 A | 0.9170 | 0.8251 | 0.7848 | 0.9059 |
| **과충전 실험만 C (최종)** | **0.9182** | **0.8344** | **0.8112** | **0.9084** |

Public: 0.8716 → 0.8770 (과충전 처리만 바꿈) → 0.8812 (과충전 배율 제외 + 아래 이미지 설정).

"Test 닮은 실험"은 Test 실험마다 입력 프로필이 가장 가까운 학습 실험 3개를 골라, 그 실험들의 OOF만으로 낸 점수입니다.

### 3-4. 이미지 모델과 비중
- **입력을 실험 기준 차이로 표현:** 실험마다 카메라 구도·배경·배터리 외형이 달라서, 현재 프레임 대신 "첫 프레임/15초 전/60초 전 대비 변화"를 입력으로 씁니다. 같은 학습 설정에서 이미지 단독 성능이 가장 좋았습니다(Validation Test 조건 Viterbi 0.773, 단일 프레임 0.761).
- **5/10/15초 간격 증강:** Test의 긴 실험 2개는 10/15초 간격으로 다운샘플돼 있어, 학습 때 격자를 무작위로 재현했습니다.
- **비중 α = 0.06:** 손으로 정하지 않고 97개 실험 5-fold OOF에서 음의 로그우도를 최소화해 추정했습니다. fold마다 0.041~0.074로 안정적이었습니다.
- **이미지가 볼 수 있는 것 (학습 없이 통계 검정, 97개 실험):** 전환 직후 15초의 이미지 변화를 같은 실험의 평상시와 비교하면, 4→5는 AUC 0.78 [0.69, 0.86]으로 뚜렷하게 변하고 2→3은 0.53 [0.45, 0.60]으로 변화가 없습니다.

## 4. 시도했지만 채택하지 않은 것 (5-fold 근거)
| 시도 | 결과 |

| CatBoost | Validation Test 조건 0.866 (LightGBM 0.914) |

## 5. 알려진 한계
- **이미지 영향력이 작습니다.** Test 이미지를 다른 실험 것으로 바꿔도 예측이 바뀌는 행은 4개(0.12%)입니다. 5-fold에서 이미지를 섞어 F1이 오르지 않아서, 우도가 정한 작은 비중만 들어가 있기 때문입니다.
- 가장 큰 남은 오류는 2→3 전환 타이밍입니다(예측이 평균 15초 늦음). 센서 임계값으로 정의되지 않는 경계입니다.
